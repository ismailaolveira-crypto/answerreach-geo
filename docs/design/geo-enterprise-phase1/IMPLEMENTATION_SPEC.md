# Phase 1 信息架构与全局数据范围实施规格

> 对应 Goal 需求：R2、R3、R10、R11
> 侧边栏设计基准：`phase1-sidebar-only-insight-hierarchy-v5-self-review-passed.png`
> 当前状态：侧边栏与 Phase 1B 全局范围栏均已完成并通过用户验收。四个洞察原页面主体仍是不可重做边界。后续进入 Phase 2 独立 image2 设计门禁，本文件不授权 Phase 2 代码实现。

### 设计范围更正（用户明确边界）

- v5 只授权改动侧边栏的层级、展开/收起、子路由选中状态和移动导航面板。
- 决策、信源、竞品、问题四个已有页面的标题、布局、卡片、表格、图表、指标、交互和数据逻辑全部保留。
- v4 桌面全页和移动 v2 全页中出现的新信源指标、排行、详情板只是误设计，不得进入代码、验收标准或数据模型。
- 全局数据范围 R3 已按独立批准的 Phase 1B 设计实现并验收；该授权不扩张为洞察页主体重做。

## 1. 这一阶段只解决什么

从企业用户的真实任务出发，本阶段只解决两个根问题：

1. 用户在任何一页都知道“自己正在看哪一段时间、哪些批次、哪些模型、哪些问题”。
2. 用户在页面之间切换时，这个数据口径不会悄悄变化。

这不是“再加一排筛选器”，而是建立全站唯一的观测口径。所有指标、行动、复测、告警和 ROI 后续都要依赖它。

## 2. 第一性原理决策

### 2.1 一个口径，一个规则

“时间、批次、模型、问题”必须是同一个整体。数字摘要、图表、表格和导出不得各自保存一份范围。

### 2.2 URL 是当前页面口径的权威表达

可复制的 URL 必须能重现同一个数据视图。本地记忆只能在 URL 没有范围参数时提供默认值，不得和 URL 暗中合并。

### 2.3 当前视图可变，历史证据不变

用户可随时更改全局范围，但行动被接受、复测被创建、告警被触发时，必须冻结当时的范围快照与指纹，不能被今天的筛选改写。

### 2.4 不支持某个维度时，要说清楚

某些页面可能尚不支持批次或多模型。过渡期间必须显示“此页暂不受批次范围影响”等明确说明，不能看起来已应用、实际被忽略。

## 3. 产品信息架构

### 3.1 六个一级入口

| 一级入口 | 当前主路由 | 包含范围 |
|---|---|---|
| 经营驾驶舱 | `/geo/{workspaceId}` | 整体经营摘要和当前观测入口 |
| 洞察 | `/geo/{workspaceId}/sources` | 决策、信源、竞品、问题四个二级页 |
| 优化行动 | `/geo/{workspaceId}/actions` | 机会、行动、负责人、交付和复测 |
| 内容 | `/geo/{workspaceId}/content` | 内容资产、审批、平台变体和 GEO 文章助手 |
| 效果与 ROI | `/geo/{workspaceId}/results` | 同口径效果、复测和业务回报 |
| 管理 | `/geo/{workspaceId}/operations` | 运营状态、模型与渠道、成员、权限和设置 |

### 3.2 洞察下钻导航（侧边栏分组，不是页面页签）

| 二级页 | 保留路由 | 处理方式 |
|---|---|---|
| 决策洞察 | `/geo/{workspaceId}/insights/decision` | 独立页面，复用且不改写原决策界面；工作区根路径继续作为经营驾驶舱入口 |
| 信源洞察 | `/geo/{workspaceId}/sources` | 独立页面，保留历史深链 |
| 竞品洞察 | `/geo/{workspaceId}/competitors` | 独立页面，保留历史深链 |
| 问题洞察 | `/geo/{workspaceId}/questions` | 独立页面，保留历史深链 |

不为了导航收缩删除或改写旧 URL。一级侧边栏只有六个分组；“洞察”展开后在其下方固定显示四个缩进子入口。当用户处于上述四个路由时，“洞察”保持选中与展开，同时只高亮当前子页。决策洞察使用独立别名路由复用原决策页面；原 `/geo/{workspaceId}` 仍保留为经营驾驶舱入口。子入口标签可使用“决策洞察”等导航文案，但不得修改对应原页面的页面名称和内容。内容区顶部不新增、删除或替换任何四页导航控件。

### 3.3 管理二级导航

- 运营状态：`/operations`
- 模型与渠道：`/admin/providers`
- 成员与权限：在管理内新增对应页签，不伪造尚未实现的权限能力
- 设置：`/settings`

## 4. 全局范围契约

### 4.1 前后端共享的领域对象

```ts
type GeoGlobalScopeV1 = {
  version: 1;
  workspaceId: number;
  period: {
    preset: "7d" | "30d" | "90d" | "365d" | "custom";
    dateFrom: string | null; // YYYY-MM-DD
    dateTo: string | null;   // YYYY-MM-DD
  };
  batchIds: number[];
  modelKeys: string[];
  questionPlanIds: number[];
  mode: "explicit" | "workspace_default";
  fingerprint: string;
};
```

规则：

- 空数组代表“全部”，不得在不同页面中一会儿表示“全部”、一会儿表示“没有数据”。
- 所有数组在生成指纹前去重、升序排列。
- `workspaceId` 来自路由，前端不允许用查询参数覆盖。
- 自定义日期范围必须同时存在 `dateFrom` 与 `dateTo`，且开始日不得晚于结束日。
- P0 安全上限：批次 100 个、模型 20 个、问题 100 个。超限必须拒绝并告知，不静默截断。

### 4.2 标准 URL

```text
/geo/1/sources?range=30d&batch=91&batch=93&model=deepseek&model=qwen&question=4&question=9
```

唯一标准键：

| 维度 | URL 键 | 方式 |
|---|---|---|
| 时间 | `range` | 单值：`7d/30d/90d/365d/custom` |
| 开始日 | `from` | 仅 `range=custom` 时存在 |
| 结束日 | `to` | 仅 `range=custom` 时存在 |
| 批次 | `batch` | 重复键，支持多选 |
| 模型 | `model` | 重复键，支持多选 |
| 问题 | `question` | 重复键，支持多选 |

兼容规则：

- 解析旧的 `period=30`、`period_days=30`、单值 `model`、单值 `question`，但一旦用户应用范围就输出新的标准 URL。
- `batch`、`model`、`question` 在序列化时统一去重并排序，保证同一范围只有一种 URL 表达。
- 将页面独有的 `tab`、`action`、`record`、`show`等参数与全局范围分开保留。
- 未知参数、不属于当前工作区的 ID、不存在的模型不得进入有效范围；界面显示一次性修正提示。

### 4.3 指纹

`fingerprint = SHA-256(canonical JSON)`。

规范化 JSON 必须：

1. 键顺序固定：`version, workspace_id, period, batch_ids, model_keys, question_plan_ids`。
2. 数组去重且升序。
3. 日期使用 `YYYY-MM-DD`，不带时区文本。
4. 不包含前端展示名称、顺序或展开状态。

指纹用于去重、对比和冻结证据，不用来代替完整快照。

## 5. 数据流与唯一数据源

### 5.1 当前视图

```text
URL 查询参数
  → 服务端 parseGeoGlobalScope()
  → 后端范围选项校验
  → 规范化 GeoGlobalScopeV1
  → 工作区布局 Provider
  → 范围栏、页面标题、API 查询、跳转链接共用同一对象
```

### 5.2 工作区默认值

- URL 存在任意全局范围键：严格使用 URL，不合并本地记忆。
- URL 没有任何范围键：优先读取该工作区最后一次有效范围；没有时使用 `30d + 全部批次 + 全部模型 + 全部问题`。
- 本地记忆的 key 包含 `workspaceId`，不得跨工作区复用。
- 本地记忆不是历史证据，不写入行动或复测结论。

### 5.3 范围选项接口

新增：

```http
GET /v1/workspaces/{workspace_id}/global-scope-options
```

返回：

- 可用的已完成观测批次（ID、时间、模型数、问题数、来源类型）。
- 当前工作区有真实观测的模型键。
- 当前问题库中的可用问题。
- 服务端默认范围与各页支持能力。

这个接口只返回选项和服务端默认值，不建立第二份可变范围状态。

### 5.4 后端查询契约

各聚合接口使用同一个 FastAPI 查询依赖 `GeoGlobalScopeQuery`，标准参数为：

```text
range, date_from, date_to, batch_ids[], model_keys[], question_plan_ids[]
```

过渡期允许 API 内部使用页面适配器，但前端不得再为每一页定义不同的范围对象。

## 6. 页面支持矩阵

| 页面 | 时间 | 批次多选 | 模型多选 | 问题多选 | Phase 1 策略 |
|---|---:|---:|---:|---:|---|
| 经营驾驶舱/决策 | 是 | 是 | 是 | 是 | 重构聚合查询，对多批次显示“所选批次”而不冒充“本次测验” |
| 信源 | 是 | 是 | 是 | 是 | 替换当前页内单选筛选器 |
| 竞品 | 是 | 是 | 是 | 是 | 同一范围契约 |
| 问题 | 是 | 是 | 是 | 是 | 业务属性筛选保留为页内筛选 |
| 优化行动 | 是 | 是 | 是 | 是 | 行动发现和网站差距分析使用同一快照 |
| 内容 | 仅上下文 | 仅上下文 | 仅上下文 | 仅上下文 | 范围栏保留，对不受影响的资产明示说明 |
| 效果与 ROI | 是 | 是 | 是 | 是 | 效果页完整应用；ROI 页用于范围内聚合及导入关联 |
| 管理 | 否 | 否 | 否 | 否 | 不显示数据范围栏，避免暗示它影响设置 |

页面内的业务属性筛选（例如问题阶段、信源搜索、行动状态）可以继续存在，但必须在视觉上低于全局范围，且不得修改全局范围。

## 7. 前端组件边界

### 7.1 新增组件

- `GeoWorkspaceShell`：识别工作区路由，组合六组侧边栏、展开子页和范围 Provider。
- `GeoGlobalScopeProvider`：提供已校验的范围对象与规范化跳转方法。
- `GeoGlobalScopeBar`：桌面端统一范围栏，包含时间、批次、模型、问题和范围摘要。
- `GeoGlobalScopeSheet`：移动端全屏/底部工作表，不压缩桌面控件。
- `GeoInsightSidebarGroup`：在侧边栏内管理洞察的展开、收起、四个独立子路由和当前页高亮。
- `GeoManagementNav`：管理页的二级导航，不和洞察的侧边层级混用。
- `GeoScopeNotice`：展示被修正的无效范围、页面未支持维度和空结果原因。

### 7.2 共享工具

- `parseGeoGlobalScope(searchParams, options)`
- `normalizeGeoGlobalScope(scope, options)`
- `serializeGeoGlobalScope(scope, pageParams?)`
- `fingerprintGeoGlobalScope(scope)`
- `mergePageParamsWithoutChangingScope(scope, pageParams)`
- `describeGeoGlobalScope(scope, options)`

上述工具必须有独立单元测试，不得散落复制到各页。

### 7.3 导航传递

侧边栏父级/子页、管理二级导航和页内跳转默认保留标准化的全局范围。只有用户点击“恢复工作区默认”才能清除。

### 7.4 四个原页面的不变边界

侧边栏改造不得改动以下页面组件树和数据调用，除非后续另有已确认的 image2 与独立需求：

- `/geo/{workspaceId}` 决策页。
- `/geo/{workspaceId}/sources` 信源页。
- `/geo/{workspaceId}/competitors` 竞品页。
- `/geo/{workspaceId}/questions` 问题页。

实施 diff 若触及上述页面的页面级 TSX、CSS 或数据函数，本切片立即停止并视为越界。允许的唯一共享改动是侧边栏从布局中向子路由传递当前 URL 与范围参数，且必须由侧边栏组件完成。

## 8. 交互和视觉验收

### 8.1 桌面端

- 左侧一级导航恰好 6 项，不把“设置”和“查看运行状态”重复表达为额外一级入口。
- 范围栏总是在每个独立洞察页的标题下方，不在页面之间跳位置。
- 洞察父级行只负责展开/收起；四个子页行负责路由跳转，不使用内容区页签模拟独立页面。
- 数量摘要仅从同一范围对象派生：例如显示“3 个批次·4 个模型·12 个问题”时，弹层选中数必须相同。
- 模型只使用 `BrandLogo` 与仓库已登记官方素材；不生产字母方块伪 Logo。
- 有效、空结果、无效参数、加载失败和部分支持都有独立状态。

### 8.2 移动端

- 不缩放桌面侧边栏，使用品牌顶栏 + 范围摘要 + 可中断导航面板。
- 移动导航面板中“洞察”也以父级分组展开四个子页，不在页面内恢复横向页签。
- 范围摘要单行可读，点击后进入分组多选工作表。
- 应用前显示选中数量；“应用”和“取消”不被安全区遮挡。
- 关闭面板不丢失当前已应用范围；未应用的草稿不污染 URL。

### 8.3 可访问性

- 按钮、标签和选项有效点击区不小于 44×44 px。
- `Tab/Shift+Tab`、方向键、`Enter/Space`、`Escape` 可完成完整范围选择。
- 弹层打开后焦点进入弹层，关闭后回到触发点。
- 读屏能读到当前选中数、应用结果与被修正的无效项。
- 支持 `prefers-reduced-motion`、减少透明度和增强对比。

## 9. 快照与历史证据

后续以下事件发生时，必须写入不可变的范围快照与指纹：

- 优化机会分析开始。
- 优化行动被接受。
- 交付目标记录真实完成。
- 针对目标创建复测。
- 定时观测计划被创建。
- 变化告警被生成。
- ROI CSV 导入批次被确认。

最低存储内容：`scope_version`、`scope_fingerprint`、`scope_snapshot_json`、`created_at`、`created_by_user_id`。任何页面显示历史结论时，使用快照而不是当前全局范围。

## 10. 实施顺序

1. 先实现范围解析、规范化、序列化、指纹和单元测试。
2. 新增范围选项 API 与后端共享查询对象。
3. 增加工作区级布局/Provider，不先改页面内容。
4. 按 image2 实现桌面和移动范围组件，使用官方 Logo。
5. 侧边栏收缩为六个父级分组，洞察在侧边栏展开四个独立子页，管理使用其自身二级导航，保留旧 URL。
6. 先迁移效果、行动、信源三个已有筛选的页面，删除其重复范围组件。
7. 再迁移决策、竞品、问题，完成全站范围矩阵。
8. 最后加入范围快照存储和历史回读，在隔离数据库副本演练迁移后才触及实时库。

## 11. 测试与验收矩阵

### 11.1 单元/契约测试

- URL 空范围、旧参数、新参数、重复值、无效 ID、越界数量、自定义日期。
- 同一集合不同顺序得到相同标准 URL 和指纹。
- 不同工作区即使范围数组相同，指纹也不同。
- URL 存在部分范围键时，不与 localStorage 隐式合并。
- 页面业务参数在改变范围后按白名单保留。

### 11.2 API 测试

- 范围选项只返回当前工作区数据。
- 未完成批次不进入默认观测范围；用户显式选择时返回可读错误。
- 多批次、多模型、多问题在决策、信源、竞品、行动和效果聚合中口径相同。
- 历史快照回读不受当前页 URL 变化影响。
- 权限不足、跨工作区 ID、非法数量和日期均失败关闭。

### 11.3 真实浏览器验收

1. 在驾驶舱选择 3 个批次、4 个模型、12 个问题，范围栏与弹层数量一致。
2. 切换到信源、竞品、问题、行动、效果，URL 和页面摘要保持一致。
3. 复制 URL 到新会话，重现相同范围。
4. 输入不存在的批次/问题，页面修正并显示明确提示，不白屏。
5. 打开历史行动/复测证据，确认展示冻结口径而非当前范围。
6. 桌面宽屏、窄屏和手机视口分别通过键盘、指针和触摸操作。
7. 减少动效、减少透明度、高对比媒体查询下依然可读可用。
8. 直达每个旧路由，页面仍可读且正确高亮新的一级导航。

## 12. Phase 1 停止条件

任何一项发生即停止继续开发，记录证据并重新规划：

- 用户尚未确认 image2 桌面和移动主要方向。
- 必须删除历史路由、历史数据或无法回滚的字段才能继续。
- 范围口径在前端和后端无法使用同一快照和指纹规则。
- 实时数据库迁移未在副本上通过完整性、外键、历史回读和回滚演练。
- 必须暴露 `.env`、密钥、会话、Cookie 或平台 token 才能测试。
- 实现与通过自审的 image2 方向存在结构性冲突，且需要重做主要交互。
- 同一根因或同一阻塞连续三个迭代仍无法解决。
- 实施需要扩展到 Goal 之外的 CRM、外部通知、自动正式发布或第三方平台密钥管理。

## 13. Phase 1 完成定义

只有以下全部成立，Phase 1 才能标记完成：

- 用户对桌面和移动 image2 主要方向明确确认。
- 六个父级分组、洞察的四个侧边子页与管理二级导航在真实浏览器中通过验收。
- 所有适用页面使用同一范围契约，不再有页面级重复范围状态。
- 批次、模型、问题全部支持多选，并且 URL 可复制重现。
