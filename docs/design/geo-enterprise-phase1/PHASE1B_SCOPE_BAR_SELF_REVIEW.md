## Apple Design 与产品自审

| 检查项 | 结果 | 证据 / 实现约束 |
|---|---|---|
| Purpose | 通过 | 唯一目标是统一时间、批次、模型和问题口径。 |
| Simplicity | 通过 | 默认态是一条连续紧凑栏，筛选和摘要没有拆成两层。 |
| Understanding | 通过 | 默认、多选、参数修正、移动工作表四个状态一眼可分。 |
| Data consistency | 通过 | 所有状态统一使用 3 个批次、4 个模型和 12 个问题，无自相矛盾。 |
| One primary action | 通过 | 桌面展开态主操作为“应用（4）”；移动态主操作为“应用范围”。 |
| Materials / depth | 通过 | 玻璃材质仅用于浮层与底部工作表，未层层叠加。 |
| Typography / contrast | 通过 | 深藏青主文字、清晰边界和克制蓝色，未用浅灰假装高级感。 |
| Official logos | 方向通过 | 设计图使用 Logo-first 排布；生成图标志只用于尺寸与间距参考，生产实现必须直接引用 `apps/web/public/brand` 中的已登记官方素材。 |
| Partial support | 通过 | 参数修正态明确告知无效批次和内容页不受批次影响。 |
| Mobile | 通过 | 不压缩桌面控件，使用摘要入口和底部工作表。 |
| Accessibility | 待实现验证 | 设计为 44px 以上点击区、显式勾选和固定操作区；键盘、焦点、读屏及降级媒体查询需在真实组件验收。 |
| Interruptibility | 待实现验证 | 弹层与工作表必须可被 Escape、取消和反向操作中断，不锁住输入。 |

## 用户审核点

1. 是否认可默认紧凑栏与一个锚定多选浮层的主形态。
2. 是否认可移动端使用底部工作表。
3. 是否认可将范围修正和“此页不支持”放在同一条组件内显示。

用户已明确通过本设计。实施必须继续遵守以下边界：只增加全局范围组件及必要的数据口径适配，不重做决策洞察、信源洞察、竞品洞察、问题洞察的原有页面主体。
