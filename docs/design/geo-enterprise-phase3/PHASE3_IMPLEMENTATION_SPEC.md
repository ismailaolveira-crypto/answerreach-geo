# Phase 3 定时观测与变化告警实现说明

## 业务链路

`固定范围计划 -> 唯一时间窗运行 -> 真实观测批次 -> 完整性门禁 -> 同口径对比 -> 去重告警 -> 确认/忽略/转行动`

## 数据对象

- `geo_observation_schedules_v1`：观测计划和固定范围快照。
- `geo_observation_schedule_runs_v1`：每个时间窗的唯一执行回执。
- `geo_change_alerts_v1`：可追溯前后批次、证据和处置状态的告警。

## 判定规则

- 品牌可见度下降：同口径、前后样本完整，下降至少 10 个百分点；超过 20 个百分点为严重。
- 竞品反超：竞品出现次数至少比基准增加 2，且高于当前品牌正向出现次数。
- 信源权重变化：某域名引用次数比基准增加至少 2。
- 模型观测异常：失败或空结果比例达到 30%；达到 50% 为严重。
- 样本不完整：只生成观测异常，禁止生成品牌升降结论。
- 同一类型 + 同一范围 24 小时冷却，避免告警轰炸。

## 运行方式

- 队列 Worker 每 30 秒检查到期计划和已完成批次。
- 时间窗使用数据库唯一约束，多次检查也只会保留一条运行。
- 计划复用现有官方 API 观测队列，不生成伪证据。
- 告警中心在管理下作为独立页面，不改动四个洞察页面主体。
