# Phase 3 观测与告警中心自审记录

## 审核结论

设计图 `phase3-alert-center-v1-self-review-passed.png` 通过自审，可进入开发。用户已明确授权普通设计节点由 Agent 自审，不再反复暂停等待人工确认。

## 第一性原理检查

- 企业真正需要的不是“曲线更多”，而是及时知道发生了什么、是否可信、该不该行动。
- 告警列表、变化对比、证据完整度和处理动作放在同一屏，不用跳转才能理解。
- 定时计划用横向卡片而非长列看板，减少页面长尾。
- 模型主要使用官方 Logo，名称不抢占主视觉。
- 不完整数据不得生成“品牌下降”结论，只能生成“观测异常”。

## 视觉自审

- Apple 浅色、克制玻璃拟态，品牌蓝是唯一主强调色。
- 红橙仅用于风险和异常，没有大面积绿色或灰色。
- 宽屏是告警列表 + 详情双栏，窄屏自动变成单栏。
- 首次浏览器自审发现 Codex 侧栏窄宽下指标文字逐字换行，已改为两列并复核通过。

## 真实性边界

- 设计图里的数字仅是布局示例，产品页不使用这些数字。
- 生产界面只读取数据库中的真实计划、批次、任务、证据和告警。
- 当前真实库已由产品页面创建 `GEO 最小真实观测验收` 计划；批次 `#96` 与 `#97` 均由官方观测队列真实完成，没有注入展示数据。
- 第一轮分发暴露出回执读取字典字段失败的问题。失败回执被原样保留并标记失败，批次 `#96` 只作为同范围历史基线；修复后第二轮回执绑定批次 `#97` 并进入 `evaluated`。
- `#96 -> #97` 产生一条真实的 `source.weight_shift` 站内告警，页面可回读范围、完整度、批次和证据；这只代表信源引用变化，不代表 GEO 优化效果或业务收益。

## 运行态回归证据

- 回执兼容 API 直接返回的字典结构，异常分发会在数据库落为 `failed`，不会永久卡在 `dispatching`。
- `tests/test_observation_alerts_v1.py` 覆盖正常分发与异常分发，两种路径都校验回执状态。
- 当前完整 API 套件为 `208 passed`；Web 类型检查、生产构建、数据库完整性、扩展契约、隐私审计与补丁检查全部通过。
- 当前验收 subject 和产品验收门报告以 `.acceptance-gate.json` 与 `.acceptance-gate/gate-report.json` 为准，文档不复制易过期的哈希值。

## 停止条件

本阶段只在以下条件同时满足后结束：

1. 真实观测计划可创建、暂停、启用、立即执行。
2. Worker 会自动检查到期计划，同一时间窗不重复创建。
3. 只有同范围且完整的前后批次才能生成品牌变化告警。
4. 告警可确认、忽略、转为真实优化行动，且可追溯批次和证据。
5. API 测试、Web 类型检查、生产构建和真实浏览器验收通过。
