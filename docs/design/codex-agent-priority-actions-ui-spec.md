# Codex Agent 优先行动 UI 实施规格

> 版本：1.0 · 对应原型：[`codex-agent-priority-actions-ui.html`](./codex-agent-priority-actions-ui.html) · [1440px 验收截图](./codex-agent-priority-actions-ui.jpg)
> 本规格是页面实现约束，原型中每个操作都必须连到真实状态或后端能力。

## 1. 页面目标

用户打开「优先行动」后，不需理解 CLI、SDK、MCP 或提示词，就能完成：

```text
选一个有真实证据的机会
→ 启动 Codex 生成
→ 看懂它正在做什么
→ 审核母稿和平台稿
→ 点击打开文章同步助手
→ 在外部平台人工发布
→ 看到后续复测进度
```

页面不是通用 Agent 聊天室，也不是任务管理看板。

## 2. 桌面结构

1440px 基准宽度下：

| 区域 | 宽度/高度 | 作用 |
|---|---|---|
| 左侧导航 | 214px 固定 | 工作区与主模块导航 |
| 页头 | 内容区顶部 | 标题、范围筛选、Codex 健康状态 |
| 机会列表 | 主区 58% | 最多展示 3 条，每条说清问题、证据、缺口和推荐平台 |
| 当前行动 | 右区 42% | 显示 Agent 任务、实时步骤、阻塞和唯一主操作 |
| 内容流水线 | 底部全宽 | 从草稿到复测的真实资产状态，自然向下流动 |

页面高度由内容决定，不在机会列表或流水线内嵌独立滚动条。

## 4. 控件与真实含义

| 控件 | 何时出现 | 点击后真实动作 | 禁用/隐藏规则 |
|---|---|---|---|
| 批次/模型/问题筛选 | 始终 | 重新查询当前范围的持久化机会 | 请求中禁用；不得继续显示旧范围结果 |
| `Codex 已连接` | diagnose 返回登录且 runtime 可用 | 打开运行时详情，显示版本/模型/最近自检 | 未连接时改为黄色「需要登录」，不显示绿点 |
| 机会行 | 有合格证据 | 选中并在右侧展示该机会当前行动 | 证据不足时用非可操作状态显示「待积累数据」 |
| `查看 N 条证据` | 机会有 evidence IDs | 跳到对应原回答/引用页并保留返回路径 | N=0 不显示 |
| `启动 Codex 生成` | 机会已选、Brief 就绪、runtime 可用 | 创建唯一 Agent run，返回 run ID 后连接 SSE | 有活动 run、证据不足或 runtime 不可用时禁用 |
| `查看实时执行` | run 已创建 | 展开有序 Agent 事件，显示当前阶段、耗时、工件与等待原因 | 没有 run 不显示 |
| `中止任务` | run 为 queued/running | 调用 interrupt，直到后端确认 cancelled 前显示「正在中止」 | 终态不显示 |
| `查看草稿` | 已产生母稿 | 打开草稿审核页，默认对比 claim 依据和平台差异 | 没有 asset ID 不显示 |
| `通过审核` | 事实门禁通过 | 写入 human review，锁定当前版本 | 仍有未确认 claim 时禁用并显示数量 |
| 平台勾选 | 有已审核平台稿 | 建立目标选择，不执行写入 | 该平台稿未审核时禁用 |
| `打开文章同步助手` | 至少勾选一个已审核平台 | 在当前浏览器检测扩展和已登录账号，打开同步确认界面 | 不得因为后端“配置过 MCP”就启用 |
| `记录发布结果` | 草稿已回读 | 用户填写真实已发布 URL，后端验证格式与目标平台 | 没有草稿回读时禁用 |

文章同步助手官方页面桥接一次只维护一个活动任务。多个平台必须按平台差异稿顺序执行，单个平台完成即回读并归档；部分失败不得覆盖已成功平台，也不得新建一个丢失既有结果的单平台进度。

## 5. Agent 进度区

进度不显示「AI 正在思考…」这种无法验证的空文案。固定显示五个业务阶段：

1. 准备事实与证据；
2. 查看目标平台规则；
3. 理解春秋元泉与采集素材；
4. 生成母稿与平台稿；
5. 核对事实并等待审核。

每个阶段只允许 `waiting / running / done / waiting_human / failed`。绿色勾只由后端已持久化的 `done` 事件触发。

顶部摘要、机会卡和右侧行动必须使用同一批次/模型/问题范围。“未闭环机会”同时包含待选择与已进入行动但未完成可比复测的机会；机会卡必须标明“待选择”或“行动进行中”。只有后端已将关联机会持久化为 `completed` 时才移出默认列表。已知模型一律显示对应真实 Logo，不使用通用“AI”图标代替。

官网审计机会不属于模型/问题批次筛选。它可以在“全部模型、全部问题”范围中与观测机会并列，但必须显示「官网原始响应 · 不计为模型观测」、审计 ID 和证据哈希；用户选择具体模型或问题后隐藏。该机会的目标平台锁定为春秋元泉官网，审核后进入人工网站部署，不开放文章同步助手。

百分比不从 token 或时间猜测，是分阶段权重：10 / 20 / 20 / 35 / 15。当某阶段正在进行时只显示该阶段起始百分比，阶段完成后再跳到下一个确定值，不做虚假缓慢增长。

实施说明（2026-08-08）：阶段状态、百分比、耗时和安全工件摘要由后端 `/agent-runs/{runId}/progress` 统一计算；页面只呈现该接口和 SSE 的持久化事实。连续相同事件允许合并显示次数，但不得删除原始事件或改变总数。

## 6. 内容流水线

仅显示已有真实对象的阶段，空阶段显示一行原因，不填造数量：

| 阶段 | 计数来源 | 卡片最小内容 |
|---|---|---|
| 内容草稿 | `geo_content_assets_v1` | 标题、版本、生成 Agent、更新时间 |
| 事实核验 | `geo_content_claims_v1` + review | 已支持/待确认数量 |
| 平台适配 | `geo_platform_variants_v1` | 真实平台 Logo、政策版本、审核状态 |
| 写入草稿 | `geo_distribution_targets_v1` | 请求/草稿回读的分离状态 |
| 人工发布 | 人工录入的真实 URL | 平台、URL、时间、操作人 |
| 等待复测 | `geo_reobservations_v1` | 复测范围、样本数和当前结论 |

## 7. Logo 规则

- 模型和平台都使用官方标识或维护良好的官方品牌图形镜像，不用首字母圆形代替。
- Logo 固定 16–20px，不改变长宽比，不自行重绘。
- 文字标签与 Logo 同时出现，不依赖颜色或图形识别。
- 原型使用 [Simple Icons](https://github.com/simple-icons/simple-icons) 的 OpenAI、知乎、微信、掘金和 CSDN 品牌 SVG；正式实现落入 `apps/web/public/brand/platforms/` 并记录来源与许可。

## 8. 响应式与无障碍

- `>= 1180px`：机会列表与当前行动左右并列。
- `768–1179px`：侧导航收缩为 76px，当前行动位于机会列表下方。
- `<768px`：单列，筛选为底部抽屉，流水线转为纵向时间线。
- 所有可点击区域至少 44×44px；键盘焦点使用 2px 主蓝轮廓。
- 文字与背景对比度满足 WCAG AA；进度不只靠颜色表达。
- `prefers-reduced-motion` 下禁用位移过渡，仅保留瞬时状态变化。

## 9. 装载、空、错误状态

- 首屏加载：保留区域骨架，不显示虚假数字。
- 无合格机会：说明当前范围无达到证据门禁的机会，提供「调整范围」，不提供「强制生成」。
- Agent 未登录：右侧保留所选机会，主操作改为「前往设置登录」。
- Agent 失败：显示最后完成阶段、可读错误码、「恢复任务」和「中止并保留工件」。
- 同步助手不存在：不改变审核和草稿状态，显示安装/启用指引。

## 10. 实现不得自由发挥的点

- 不把右侧「当前行动」改成聊天框。
- 不把底部流水线改成一排永远有数字的假看板。
- 不为了展示“AI 感”加入无数据来源的思考文本、打字动画或虚假百分比。
- 不合并「已请求同步」、「草稿已保存」、「已发布」和「复测完成」。
- 不在小卡片内做独立滚动；内容变长时页面自然向下延伸。
